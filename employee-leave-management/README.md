## 🎯 Problem Statement
Develop a REST API using **Node.js** and **Express.js** to manage employee leave requests. The application maintains all leave-request records in an in-memory JavaScript array without requiring an external database.

---

## 🗄 Data Model & Initial Data

### Record Structure
| Field | Data Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `id` | Number | Unique identifier | Auto-generated by application (numeric, max+1) |
| `employeeName` | String | Full name of the employee | Non-empty string |
| `employeeCode` | String | Unique code of the employee | Non-empty string (e.g. `EMP101`) |
| `leaveType` | String | Type of leave requested | Must be one of: `Casual`, `Sick`, `Earned` |
| `days` | Number | Number of days requested | Positive integer (`> 0`) |
| `status` | String | Current status of the request | Must be one of: `Pending`, `Approved`, `Rejected` |

## ⚡ Important Implementation Note
> Specific routes (`/api/leaves/pending` and `/api/leaves/filter`) are explicitly declared **before** the parameterized dynamic route (`/api/leaves/:id`) in `server.js`. This guarantees that `"pending"` and `"filter"` are never erroneously interpreted as dynamic numeric IDs.

## 📡 API Endpoints & Specifications

### 1. GET All Records
- **Endpoint:** `GET /api/leaves`
- **Status Code:** `200 OK`
- **Response:**
  ```json
  [
    {
      "id": 701,
      "employeeName": "Ananya Singh",
      "employeeCode": "EMP101",
      "leaveType": "Casual",
      "days": 2,
      "status": "Pending"
    },
    ...
  ]
  ```

---

### 2. GET Pending Leave Requests
- **Endpoint:** `GET /api/leaves/pending`
- **Status Code:** `200 OK` (even if no pending records exist)
- **Response:**
  ```json
  [
    {
      "id": 701,
      "employeeName": "Ananya Singh",
      "employeeCode": "EMP101",
      "leaveType": "Casual",
      "days": 2,
      "status": "Pending"
    }
  ]
  ```

---

### 3. Filter Records by Status (Case-Insensitive)
- **Endpoint:** `GET /api/leaves/filter?status=<value>`
- **Query Parameter:** `status` (e.g. `pending`, `Pending`, `Approved`, `rejected`)
- **Status Codes:**
  - `200 OK` if matches found (or `[]` if none match)
  - `400 Bad Request` if `status` query parameter is missing
- **Examples:**
  - `GET /api/leaves/filter?status=approved`
  - `GET /api/leaves/filter?status=REJECTED`
  - `GET /api/leaves/filter?status=nonexistent` -> returns `[]` with `200 OK`

---

### 4. GET Leave Request by ID
- **Endpoint:** `GET /api/leaves/:id`
- **Status Codes:**
  - `200 OK` when record is found
  - `404 Not Found` when record does not exist
  - `400 Bad Request` if `:id` is not a valid number
- **Response (200 OK):**
  ```json
  {
    "id": 701,
    "employeeName": "Ananya Singh",
    "employeeCode": "EMP101",
    "leaveType": "Casual",
    "days": 2,
    "status": "Pending"
  }
  ```

---

### 5. POST a New Leave Request
- **Endpoint:** `POST /api/leaves`
- **Headers:** `Content-Type: application/json`
- **Status Codes:**
  - `201 Created` on valid input
  - `400 Bad Request` on validation failure
- **Sample Request Body:**
  ```json
  {
    "employeeName": "Vikram Das",
    "employeeCode": "EMP104",
    "leaveType": "Earned",
    "days": 2,
    "status": "Pending"
  }
  ```
- **Response (201 Created):**
  ```json
  {
    "id": 704,
    "employeeName": "Vikram Das",
    "employeeCode": "EMP104",
    "leaveType": "Earned",
    "days": 2,
    "status": "Pending"
  }
  ```

---

### 6. PUT / Update a Leave Request
- **Endpoint:** `PUT /api/leaves/:id`
- **Headers:** `Content-Type: application/json`
- **Status Codes:**
  - `200 OK` on successful update
  - `404 Not Found` if ID does not exist
  - `400 Bad Request` if input validation fails
- **Sample Request Body:**
  ```json
  {
    "employeeName": "Ananya Singh",
    "employeeCode": "EMP101",
    "leaveType": "Casual",
    "days": 2,
    "status": "Approved"
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "id": 701,
    "employeeName": "Ananya Singh",
    "employeeCode": "EMP101",
    "leaveType": "Casual",
    "days": 2,
    "status": "Approved"
  }
  ```

---

### 7. DELETE a Leave Request
- **Endpoint:** `DELETE /api/leaves/:id`
- **Status Codes:**
  - `200 OK` on successful deletion
  - `404 Not Found` if ID does not exist
- **Response (200 OK):**
  ```json
  {
    "message": "Leave request with ID 702 deleted successfully.",
    "deletedRecord": {
      "id": 702,
      "employeeName": "Rahul Verma",
      "employeeCode": "EMP102",
      "leaveType": "Sick",
      "days": 1,
      "status": "Approved"
    }
  }
  ```

### 3. cURL Commands

```bash
# 1. Get All Leaves
curl -X GET http://localhost:5000/api/leaves

# 2. Get Pending Leaves
curl -X GET http://localhost:5000/api/leaves/pending

# 3. Filter by Status (case-insensitive)
curl -X GET "http://localhost:5000/api/leaves/filter?status=approved"

# 4. Get by ID
curl -X GET http://localhost:5000/api/leaves/701

# 5. Create New Leave
curl -X POST http://localhost:5000/api/leaves \
  -H "Content-Type: application/json" \
  -d '{"employeeName":"Vikram Das","employeeCode":"EMP104","leaveType":"Earned","days":2,"status":"Pending"}'

# 6. Update Leave
curl -X PUT http://localhost:5000/api/leaves/701 \
  -H "Content-Type: application/json" \
  -d '{"employeeName":"Ananya Singh","employeeCode":"EMP101","leaveType":"Casual","days":2,"status":"Approved"}'

# 7. Delete Leave
curl -X DELETE http://localhost:5000/api/leaves/702
```
